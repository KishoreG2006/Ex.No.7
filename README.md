## Developing a Prompt-Based Application Using Large Language Models

# 1. Aim

To develop a prompt-based application using a Large Language Model (LLM) to generate and improve technical communication artifacts such as a technical report, research abstract, literature review, project proposal, resume, LinkedIn profile, and research poster through iterative prompting.

---

# 2. Objectives

The objectives of this experiment are:

* To understand prompt engineering for technical communication.
* To generate different professional and academic documents using LLMs.
* To design prompts according to the requirements of each document.
* To improve generated content through iterative prompting.
* To evaluate generated content for grammar and readability.
* To verify technical accuracy.
* To reduce plagiarism and ensure originality.
* To develop a complete technical communication portfolio.
* To understand how LLMs can support academic and professional writing.

---

# 8. Initial Prompt

The initial prompt establishes the role and purpose of the AI assistant.

```text
Act as a professional technical communication assistant.

Help me create high-quality academic and professional documents
for my engineering studies and software projects.

The content should be:
- technically accurate
- grammatically correct
- easy to understand
- professionally written
- original
- well structured

Ask for or use the available project information before generating
technical content.

Do not invent technical specifications, results, references,
achievements, or project outcomes.
```

---

# 9. Iterative Prompting Strategy

The content is improved through multiple iterations.

### Iteration 1 — Basic Generation

```text
Create the requested document using the project information provided.
Use a clear and professional structure.
```

### Iteration 2 — Technical Improvement

```text
Improve the technical accuracy of the document.

Check:
- terminology
- technical claims
- system architecture
- methodology
- algorithms
- implementation details

Do not introduce unsupported information.
```

### Iteration 3 — Readability Improvement

```text
Improve the readability of the document.

Use:
- short and clear sentences
- appropriate headings
- logical paragraphs
- professional technical language

Remove unnecessary repetition.
```

### Iteration 4 — Grammar Improvement

```text
Proofread the document for grammar, spelling,
punctuation and sentence structure.

Preserve the original technical meaning.
```

### Iteration 5 — Originality Improvement

```text
Rewrite the content in original language.

Avoid generic copied phrases and unnecessary repetition.
Preserve all technical facts and meaning.

Do not fabricate information.
```

### Iteration 6 — Final Review

```text
Perform a final quality review.

Evaluate the document for:
1. Grammar
2. Technical accuracy
3. Originality
4. Readability
5. Structure
6. Professional quality

List any remaining issues and provide the corrected version.
```

# 19. Technical Accuracy

The generated content is checked for:

* Correct terminology
* Correct technical concepts
* Valid methodology
* Accurate descriptions
* Unsupported claims
* Fabricated results
* Incorrect specifications

AI-generated technical content must be verified against actual project documentation and implementation.

---

# 20. Plagiarism / Originality

The content is reviewed for:

* Direct copying
* Repeated generic phrases
* Unoriginal descriptions
* Excessive similarity to existing material

The LLM is instructed to generate original wording while preserving verified technical information.

> AI-generated content should not automatically be considered plagiarism-free. Final content should be checked using an appropriate plagiarism/similarity detection system.

---

# 21. Readability

Readability is evaluated based on:

* Sentence length
* Paragraph organization
* Vocabulary
* Technical clarity
* Logical flow
* Use of headings
* Ease of understanding

The final version should be understandable to its intended audience without removing necessary technical terminology.

# 24. Prompt Engineering Techniques Used

### 1. Role Prompting

The AI is given a specific role.

```text
Act as a professional technical report writer.
```

### 2. Context Provision

Relevant project information is provided before generation.

```text
The project is a smartphone-based accident detection system.
```

### 3. Constraint Prompting

Restrictions are explicitly defined.

```text
Do not invent experimental results.
```

### 4. Format Specification

The expected structure is clearly specified.

```text
Include Introduction, Methodology, Results and Conclusion.
```

### 5. Iterative Refinement

The generated output is repeatedly reviewed and improved.

```text
Improve grammar and technical accuracy without changing
the original meaning.
```

# 28. Key Observations

1. Prompt quality strongly affects LLM output quality.
2. Providing sufficient context improves technical relevance.
3. Role-based prompts improve the style of generated documents.
4. Explicit constraints help prevent unsupported claims.
5. Iterative prompting improves grammar and readability.
6. Technical accuracy must be independently verified.
7. AI-generated content requires originality/plagiarism checking.
8. Different document types require different prompt structures.
9. LLMs can significantly reduce the initial effort required for technical documentation.
10. Human review remains necessary for final academic and professional communication.

# 30. Conclusion

This experiment demonstrated how prompt engineering can be used to develop a practical AI-assisted technical communication system.

The **AI Technical Communication Assistant** provides a structured approach for generating and refining academic and professional documents. Instead of relying on a single prompt, iterative prompting was used to progressively improve the quality of the generated content.

The experiment shows that LLMs can support students in technical writing, research communication and professional profile development. However, AI-generated content must be reviewed for technical correctness, originality, factual accuracy and suitability for its intended audience.

The final workflow can be summarized as:

```text
Good Requirements
        +
Effective Prompt
        +
LLM Generation
        +
Iterative Refinement
        +
Human Verification
        =
High-Quality Technical Communication
```
